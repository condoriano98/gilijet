## App findings (not fixed here)

Tracked as bugs in `docs/spikes/in-progress/BUGS_QA_BASELINE_FINDINGS.md` (ids B1 to B11), with the re-test log to fill after the redesign.

1. **Open redirect** on sign-in and register through `next` (AUTH-013 confirmed by this run). Security. Needs its own ticket.
2. **Terms error text:** an unticked box on `/book` shows `Expected string, received null` (BOOK-F05b confirmed). Cause: `agreedToTerms: z.string().optional()` rejects the `null` that an unticked checkbox sends. The browser's own `required` normally hides this.
3. **Soft 404:** an unknown booking reference or departure id returns HTTP **200** with the not-found page, because those pages stream behind `loading.tsx` before calling `notFound()`. `/pay` and `/checkout` return a real 404. Matters for monitoring and crawlers, not for visitors.
4. **Missing h1** on `/b`, `/best-price-guarantee` and the sign-in page; **no page title** of its own on `/best-price-guarantee`.
5. From reading the code, not yet exercised: `/account?ok=` and `?error=` print any text from the URL; forgot-password has no rate limit; account matches bookings by exact-case email; `/refunds` and `/change-plans` hard-code 48/168/7 (CONT-024/025 guard them against `REFUND_CUTOFF_HOURS`); search max-price and price sort read `basePrice`, not the seasonal price; cancelling an unpaid booking more than 7 days out seems to create a full PENDING refund; no language switcher; no custom `not-found.tsx`; Terms and Privacy sections have no `id` anchors.
